## Fix strongly recommended

### F1 Saves can land out of order, so an older town can be stored last

- **Rework if left:** high
- **Effort:** S
- **Evidence:** `apps/web/src/saves.ts:101` "const db = await open();"
- **Case:** Every save opens its own database connection and only then starts its transaction. Two saves issued close together (an import's write and the old town's save-on-hide, or an autosave and a hide) can start their transactions in the other order. The older state is then the one kept. The S2 fix for out-of-order writes covers only the "Saved at tick" label, not the stored record. The player loses the imported or newer town without a message.
- **Fix:** Send all writes through one open connection or one promise chain, so they run in call order. Add a test that issues two saves in one task and reads back the later one.

### F2 A failed save is invisible

- **Rework if left:** high
- **Effort:** S
- **Evidence:** `apps/web/src/App.tsx:181` "() => {},"
- **Case:** A rejected save (storage full, storage cleared by the browser, a blocked open) is swallowed. The only sign is that "Saved at tick" stops rising. Morgan did not look at the Storage line on his phone, so whether Android keeps this data is still unknown. A player can play for hours on a town that is not being saved.
- **Fix:** After 2 failed saves in a row, show "Saving failed. Export a save." in the existing notice slot, and clear it on the next success.

### F3 An installed app has no way to take an update

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `apps/web/vite.config.ts:25` "registerType: 'prompt',"
- **Case:** The M0 spec chose this: a new version takes over only once every window of the app has closed, and no code prompts or reloads. An installed app left in the recents list can run an old build for days. M1 changes the save schema. An old client that meets a newer save shows the "newer version" refusal with no button that updates it. The manifest also has no `id` and no maskable icon.
- **Fix:** In M1's first slice, register through the plugin's update hook and show "Update ready, reload". Add a manifest `id` and a maskable icon in the same change.

## Other findings

### F4 Import Replace keeps no copy of the town it replaces

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `apps/web/src/saves.ts:108` "tx.objectStore(STORE).put(record, KEY);"
- **Case:** There is one record. Replace writes the imported town over it, on the running page and on the refused-save screens. The confirm names the ticks, but a save that a later app version could have read is gone unless the player exported first.
- **Fix:** In the same transaction, copy the old record to a second key, `previous`.

### F5 The save shape check accepts numbers that break the clock

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `apps/web/src/saves.ts:37` "].every(isWhole)"
- **Case:** The whole-number test passes values far above 2^53, where tick arithmetic loses precision, and food above the cap. Entries in `residents` are not checked at all, and the import has no size limit. A hand-edited or damaged file loads and then misbehaves. M1 adds many fields to this check.
- **Fix:** Use `Number.isSafeInteger`, check food against the cap, check each resident's shape and cap the import at about 5 MB. Make "a new field means a parse check and an upgrade step" a line in the M1 spec.

### F6 A crashed worker freezes the town with no message

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `apps/web/src/App.tsx:212` "waitingRef.current = true;"
- **Case:** The flag is cleared only when the worker answers. If the worker throws, no answer comes, the timer returns early for ever and the page looks alive. Nothing listens for the worker's error events. M1's catch-up does far more work per tick, so this gets more likely.
- **Fix:** Handle the worker's `error` and `messageerror` events: show a notice and offer Export of the standby copy.

### F7 Save-on-hide has no test, and two browser tests assert nothing

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `tests/browser/smoke.spec.ts` absent: searched visibilitychange, pagehide, hidden, dispatchEvent in tests/browser and apps/web/test
- **Case:** The standby copy written on hide is the main defence for a closed app, and no test fails if its listeners are removed. The storage-line test accepts either answer, and the offline test reads the service worker's state without asserting it.
- **Fix:** Add a browser test that changes the foragers, hides the page and reads the stored record. Assert the service worker state and stub the storage answer both ways.

### F8 The engine purity check has holes and no test of its own

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `scripts/check-sim-purity.mjs:27` "(?<![\\w$.])"
- **Case:** The pattern ignores a banned word that follows a dot, so `globalThis.Date.now()` passes. Comment stripping also blanks the rest of a line after `//` inside a string. No test calls `findBanned`, so the check could break and stay green. This check guards the rule that catch-up equals live play (D-002).
- **Fix:** Ban `globalThis`, `crypto` and `Intl`, drop the dot from the lookbehind for `Date` and `performance`, and add a Vitest file of known-bad and known-clean snippets.

### F9 The determinism test cannot fail

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `packages/sim/src/step.ts:64` "const result = step(current, [], content);"
- **Case:** `advance` is a loop over `step`, and the test compares `advance` with a loop over `step`. The real risk, a command arriving between two catch-up chunks, is untested. `advance` also accepts a negative, fractional or infinite tick count without complaint.
- **Fix:** Test advance, command, advance against the same run tick by tick. Make `advance` throw on a tick count that is not a whole number of 0 or more.

### F10 The order of commands and production inside a tick is untested

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `packages/sim/test/step.test.ts:50` "const set = step(start, [{ type: 'setForagers', count: 3 }], content);"
- **Case:** The only test that sends a command runs at tick 0, where nothing is produced. If production ran before the command was applied, every test would still pass. M1 puts many commands through this path.
- **Fix:** Add a test on a production tick that sends a command and checks food and the random stream after it.

### F11 The soak checks little and runs at the cap

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `scripts/soak.ts:32` "!Number.isInteger(food)"
- **Case:** It checks the food range and the tick count only. Today's run ended with food 200 of 200 and 5,422 lost, so it sat at the cap for most of 10,000 ticks and exercised little. A broken random stream or a broken `advance` would still exit 0.
- **Fix:** Check the random stream's range and the foragers' bounds each tick, and compare a second pass that uses `advance`. M1 replaces the bot anyway; carry these invariants over.

### F12 The bundle check measures only the entry script

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `scripts/check-bundle.mjs:10` "const tag = html.match("
- **Case:** WEB-06 asks for the entry plus preloaded chunks. The worker bundle, the CSS and any preloaded chunk are not counted. If M1 splits code, the entry shrinks, the check passes and the real first load grows.
- **Fix:** Sum the entry, every `modulepreload` link and the worker asset, and fail on the total.

### F13 Engine and page shapes are M0-only and M1 must replace them together

- **Rework if left:** medium
- **Effort:** M
- **Evidence:** `packages/sim/src/types.ts:22` "stock: { food: number };"
- **Case:** Stock has one fixed key, the command handler never reads the command's type, stream names are a closed list of two, content has no validation, and the worker posts the whole state to the page on every tick with no message version. None is wrong for M0. All five change in M1, and the save upgrade from schema 1 to 2 does not exist yet.
- **Fix:** Put these in the M1 spec's first slice: stock as a record by resource id, a `switch` on command type, a naming rule for streams recorded in DECISIONS, `validateContent`, and a schema 2 upgrade with a test that loads a schema 1 save.

### F14 Replace leaves the page clock on the old town for one tick

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `apps/web/src/App.tsx:244` "const replaceWith = (record: SaveRecord) => {"
- **Case:** After an import the page keeps the old town's time anchor until the worker answers. The 1-second timer can fire first and advance the imported town by a tick it did not earn.
- **Fix:** Set the anchor and the waiting flag from the imported record before posting it to the worker.

### F18 The icons' font has no recorded source or licence

- **Rework if left:** low
- **Effort:** S

### F19 Without the lock, two windows can both run the town
