# Lessons

One line per mistake. Read the entries for an area before working in it. When a mistake repeats, bump its count; at ×2 it also becomes a rule (in DECISIONS, AGENTS.md, or proposed to AI-Master-Instructions). Mark retired entries SUPERSEDED; never delete them.

Format: `- <area> · <mistake> · <root cause> · <rule> · ×<n> (<YYYY-MM-DD>)`

- docs · the charter stated guesses about adventure-manager, Story-Generator and Project-Vulcan as facts, and one claim (earlier projects had no playable loop) was false · written from chat memory before the repos were read · read a named repo's README, HANDOFF and DECISIONS headings before describing it; label anything unread as a guess · ×1 (2026-11-09)
- ci · the first CI run failed at `npm ci` with EBADENGINE (Node 24.19.0 came with npm 11.17.0, the repo pins 11.9.0 with engine-strict) · the master's `ci.yml` template has no npm pin step and the spec copied it; local checks ran through `npm exec --package=npm@11.9.0`, so they could not see it · a workflow that pins npm installs that npm before `npm ci`, as Project-Vulcan's does; propose the step for the master template · ×1 (2026-11-09)
- spec · the spec's Playwright `webServer` command (`npm run preview -- --port 4173 --strictPort`) never started: the root script calls a workspace script, and npm kept the flags instead of passing them to Vite · the command was copied from a one-package repo and never run in the prototype · run every command a spec quotes once in the prototype; a root script that forwards to a workspace ends with `--` · ×1 (2026-11-09)
- tests · undoing a planted bug with `git checkout <file>` threw away the file's uncommitted work (`importText`, `storageAnswer`), found only because `git status` no longer listed it · the file had real changes that were never committed or copied before the plant · copy a file to the scratchpad before planting a bug in it and restore from the copy, or commit first; never `git checkout` a file with uncommitted work · ×1 (2026-11-10)
- spec · the M1 spec's first draft let a one-worker building run a method with inputs from an empty store (the shortage test floored the amount owed), counted departures by calendar season so four could fall in one night, and had a wood dead end · the rules were written and modelled in the same head; the scratch model had the same floor bug · fresh checks before approval: critic found 3 high (all fixed), the re-check found 1 high (fixed); paraphrase was right; zero-decisions listed about 60 open choices over two passes, the last fix pass was not re-read; fixed 30 or so findings, contested 2, escalated 0 · ×1 (2026-11-10)
- spec · the M1 spec's J1 check failed a save by replacing `indexedDB.open`, though the same spec makes saves reuse one connection, so the replaced call is never made; F14's fix as written would also have frozen the clock after an import · the check and the design were written in different passes and neither was run · the S1 zero-decision check found both before any code; when a spec changes how something is done, re-read every check that reaches it · ×1 (2026-11-10)
